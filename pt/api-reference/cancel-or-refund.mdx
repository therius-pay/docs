Se você não quer rastrear no seu próprio sistema se um pagamento está no estado `authorized` ou `captured`, `POST /payment/{id}/cancel_or_refund` faz isso por você. O Therius verifica o estado atual do pagamento e automaticamente cancela a autorização (se não capturada) ou emite um reembolso total (se já capturada). Isso é especialmente útil em fluxos de reversão de pedidos onde o estado do pagamento pode variar conforme o momento — por exemplo, um cliente cancelando um pedido enquanto o cumprimento está em andamento.

<SchemaLangNote lang="pt" />

## Identificar o pagamento

`{id}` é o `id` de pagamento do Therius devolvido por `POST /payment/authorization` e `POST /payment/purchase`. `orderCode` e `paymentCode` são os seus próprios campos de referência e **não** são aceitos aqui. Um `id` desconhecido ou não pertencente devolve `404`.

## Requisição

**Endpoint:** `POST https://api.therius.io/v1/payment/{id}/cancel_or_refund`

### Parâmetros de caminho

<ParamField path="id" type="string" required>
  O `id` de pagamento do Therius da resposta de autorização/purchase.
</ParamField>

### Headers

<ParamField header="Authorization" type="string">
  A sua chave de API secreta como token Bearer: `Bearer sk_live_xxx` (produção) ou `Bearer sk_sandbox_xxx` (sandbox).
</ParamField>

<ParamField header="Idempotency-Key" type="string">
  Um UUID que você gera por operação. Obrigatório em produção para prevenir operações duplicadas em uma nova tentativa.
</ParamField>

<ParamField header="Content-Type" type="string" required>
  Deve ser `application/json`.
</ParamField>

### Corpo da requisição

<ParamField body="merchantCode" type="string" required>
  O seu identificador de lojista.
</ParamField>

<ParamField body="reference" type="string">
  Uma referência interna opcional para esta operação.
</ParamField>

<Note>
  Este endpoint sempre reverte o pagamento **completo** — anula toda a retenção de autorização, ou reembolsa todo o valor capturado. Para emitir um reembolso *parcial* em um pagamento capturado, chame [Refund](/api-reference/refund) com um `amount` em vez disso.
</Note>

## Resposta

<ResponseField name="id" type="string">
  O `id` de pagamento do Therius (o mesmo valor que o segmento de caminho `{id}`).
</ResponseField>

<ResponseField name="status" type="string">
  A ação tomada. Um de:

  - `"cancelled"` — a autorização foi anulada (o pagamento estava no estado `authorized`).
  - `"refunded"` — os fundos foram devolvidos ao titular do cartão (o pagamento estava no estado `captured`).
  - `"failed"` — a operação não pôde ser concluída.
</ResponseField>

<ResponseField name="paymentCode" type="string">
  O ID de recibo do Therius para o pagamento original.
</ResponseField>

<ResponseField name="orderCode" type="string">
  O seu `orderCode` original.
</ResponseField>

<ResponseField name="merchantCode" type="string">
  O seu `merchantCode`.
</ResponseField>

<ResponseField name="amount" type="object">
  O valor cancelado ou reembolsado, em formato `{ currency, value, exponent }`.
</ResponseField>

## Exemplo

### Reverter um pagamento sem conhecer o estado dele

<RequestExample>

```bash cURL
curl -X POST https://api.therius.io/v1/payment/9f8b2c1e-4d5a-6b7c-8d9e-0f1a2b3c4d5e/cancel_or_refund \
  -H "Authorization: Bearer sk_live_your_key_here" \
  -H "Idempotency-Key: $(uuidgen)" \
  -H "Content-Type: application/json" \
  -d '{
    "merchantCode": "MERCHANT_001"
  }'
```

</RequestExample>

<ResponseExample>

```json 200 OK
{
  "id": "9f8b2c1e-4d5a-6b7c-8d9e-0f1a2b3c4d5e",
  "status": "cancelled",
  "paymentCode": "PC-1234567890",
  "orderCode": "ORDER-20240101-002",
  "merchantCode": "MERCHANT_001",
  "amount": { "currency": "USD", "value": 9900, "exponent": 2 }
}
```

</ResponseExample>

**Resposta quando o pagamento estava capturado (caminho de reembolso) — `200 OK`**

```json
{
  "id": "9f8b2c1e-4d5a-6b7c-8d9e-0f1a2b3c4d5e",
  "status": "refunded",
  "paymentCode": "PC-1234567890",
  "orderCode": "ORDER-20240101-001",
  "merchantCode": "MERCHANT_001",
  "amount": { "currency": "USD", "value": 4999, "exponent": 2 }
}
```

<Tip>
  Este endpoint é ideal para fluxos de reversão de pedidos disparados pela sua UI de cancelamento voltada ao cliente, onde o mesmo caminho de código trata tanto os estados anteriores à captura quanto os posteriores. Use o `status` na resposta para determinar qual ação foi tomada e atualize os seus registros internos de acordo.
</Tip>
