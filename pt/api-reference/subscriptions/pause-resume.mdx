Pausar uma assinatura para todas as tentativas de renovação sem cancelá-la, preservando o registro da assinatura e todo o histórico dela. Retomar restaura o faturamento e recalcula a próxima data de faturamento para frente a partir da data atual — o cliente não é cobrado pelo tempo decorrido enquanto esteve pausada.

<SchemaLangNote lang="pt" />

## Pausar uma assinatura

`POST /subscription/{id}/pause` suspende o faturamento de uma assinatura ativa. Dispara o evento de webhook `subscription.paused` e move a assinatura para o status `paused`.

<Note>
  Somente assinaturas no status `active`, `trialing` ou `past_due` podem ser pausadas. Tentar pausar uma assinatura `cancelled`, `completed` ou já `paused` devolve um erro `400`.
</Note>

### Requisição

**Endpoint:** `POST /subscription/{id}/pause`

### Headers

<ParamField header="Authorization" type="string" required>
  `Bearer sk_live_xxx` (produção) ou `Bearer sk_sandbox_xxx` (sandbox) — a sua chave de API privada de lojista.
</ParamField>

<ParamField header="Content-Type" type="string" required>
  `application/json`
</ParamField>

<ParamField header="Idempotency-Key" type="string">
  Um UUID que você gera por operação. Repetir com a mesma chave devolve a resposta original em vez de repetir a operação. Recomendado em produção.
</ParamField>

### Parâmetros de caminho

<ParamField path="id" type="string" required>
  O UUID da assinatura a pausar.
</ParamField>

### Corpo da requisição

<ParamField body="merchantCode" type="string" required>
  O seu identificador de conta de lojista.
</ParamField>

### Exemplo

```bash
curl -X POST https://api.therius.io/v1/subscription/sub_abc123def456/pause \
  -H "Authorization: Bearer sk_live_your_key_here" \
  -H "Content-Type: application/json" \
  -d '{ "merchantCode": "MERCHANT_001" }'
```

## Retomar uma assinatura

`POST /subscription/{id}/resume` restaura o faturamento de uma assinatura pausada ou suspensa, com um comportamento ligeiramente diferente conforme o status atual.

| Status atual | Comportamento ao retomar |
| --- | --- |
| `paused` | Faturamento restaurado. Próxima data de faturamento = hoje \+ intervalo do plano. |
| `suspended` | O Therius tenta uma nova cobrança imediata (MIT). Devolve `402` se recusada. |

<Warning>
  Se retomar a partir de `suspended` devolver `402` (cartão recusado), você deve primeiro atualizar o método de pagamento usando `POST /subscription/{id}/payment-method` antes de tentar retomar novamente.
</Warning>

Em caso de sucesso, o Therius dispara `subscription.resumed`. Se uma assinatura `suspended` for revivida por uma cobrança bem-sucedida, ele também dispara `subscription.reactivated`.

### Requisição

**Endpoint:** `POST /subscription/{id}/resume`

### Headers

<ParamField header="Authorization" type="string" required>
  `Bearer sk_live_xxx` (produção) ou `Bearer sk_sandbox_xxx` (sandbox) — a sua chave de API privada de lojista.
</ParamField>

<ParamField header="Content-Type" type="string" required>
  `application/json`
</ParamField>

<ParamField header="Idempotency-Key" type="string">
  Um UUID que você gera por operação. Repetir com a mesma chave devolve a resposta original em vez de repetir a operação. Recomendado em produção.
</ParamField>

### Parâmetros de caminho

<ParamField path="id" type="string" required>
  O UUID da assinatura a retomar.
</ParamField>

### Corpo da requisição

<ParamField body="merchantCode" type="string" required>
  O seu identificador de conta de lojista.
</ParamField>

### Erros

| Código | Significado |
| --- | --- |
| `400` | A assinatura não está em um estado retomável (p. ex. já `active` ou `cancelled`). |
| `402` | A retomada a partir de `suspended` falhou — a nova cobrança imediata foi recusada. |
| `404` | Assinatura não encontrada. |

### Exemplo

```bash
curl -X POST https://api.therius.io/v1/subscription/sub_abc123def456/resume \
  -H "Authorization: Bearer sk_live_your_key_here" \
  -H "Content-Type: application/json" \
  -d '{ "merchantCode": "MERCHANT_001" }'
```
