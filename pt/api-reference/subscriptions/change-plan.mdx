Use `POST /subscription/{id}/change-plan` para mover um assinante para um plano diferente — seja fazendo upgrade para um nível de preço maior ou downgrade para um menor. Você controla se a mudança entra em vigor de imediato (com o rateio cobrado ou absorvido hoje) ou é programada para o próximo ciclo de faturamento.

<SchemaLangNote lang="pt" />

<Note>
  O `amount`, o `interval` e o `intervalCount` de um plano são imutáveis assim que ele tem assinantes ativos. Para mudar o preço ou a cadência, crie um novo plano e use este endpoint para migrar assinantes para ele.
</Note>

## Requisição

**URL base:** `https://api.therius.io/v1`

**Endpoint:** `POST /subscription/{id}/change-plan`

### Headers

<ParamField header="Authorization" type="string" required>
  `Bearer sk_live_xxx` (produção) ou `Bearer sk_sandbox_xxx` (sandbox) — a sua chave de API privada de lojista.
</ParamField>

<ParamField header="Content-Type" type="string" required>
  `application/json`
</ParamField>

<ParamField header="Idempotency-Key" type="string">
  Um UUID que você gera por operação. Repetir com a mesma chave devolve a resposta original em vez de repetir a operação. Recomendado em produção.
</ParamField>

### Parâmetros de caminho

<ParamField path="id" type="string" required>
  O UUID da assinatura a atualizar.
</ParamField>

### Corpo da requisição

<ParamField body="merchantCode" type="string" required>
  O seu identificador de conta de lojista.
</ParamField>

<ParamField body="planId" type="integer" required>
  ID do plano de destino para o qual mover o assinante. O plano deve estar ativo e disponível no país do assinante.
</ParamField>

<ParamField body="applyAt" default="next_billing" type="string">
  Controla quando a mudança de plano entra em vigor. Valores aceitos:

  - `"now"` — aplica-se de imediato. Para upgrades, a diferença rateada pelo restante do período de faturamento atual é cobrada como uma Merchant Initiated Transaction (MIT) de imediato. Para downgrades, nenhum reembolso é emitido; o preço menor entra em vigor a partir do próximo ciclo.
  - `"next_billing"` — o novo plano é programado para a próxima data de renovação do assinante. O período de faturamento atual é concluído na tarifa existente.
</ParamField>

## Resposta

Devolve `200 OK` com o objeto de assinatura atualizado. Quando `applyAt` é `"next_billing"`, a resposta inclui um objeto `scheduledPlanChange` com o `planId` e o timestamp `effectiveAt`.

## Erros

| Código | Significado |
| --- | --- |
| `400` | Plano de destino não encontrado, inativo ou não disponível no país do assinante. |
| `402` | A cobrança de rateio imediato foi recusada (apenas quando `applyAt: "now"`). |
| `404` | Assinatura não encontrada. |
| `422` | Erro de validação. |

<RequestExample>

```bash cURL
curl -X POST https://api.therius.io/v1/subscription/sub_abc123def456/change-plan \
  -H "Authorization: Bearer sk_live_your_key_here" \
  -H "Idempotency-Key: $(uuidgen)" \
  -H "Content-Type: application/json" \
  -d '{
    "merchantCode": "MERCHANT_001",
    "planId": 99,
    "applyAt": "now"
  }'
```

</RequestExample>

<ResponseExample>

```json 200 OK
{}
```

</ResponseExample>

<Tip>
  Se você quer oferecer um período introdutório com desconto no novo plano, crie o novo plano com `introAmount` e `introBillingCycles` definidos antes de executar `change-plan`. O assinante receberá o preço introdutório a partir do primeiro ciclo dele no novo plano.
</Tip>
