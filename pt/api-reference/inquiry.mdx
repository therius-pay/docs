Use `GET /payment/inquiry/{id}` para recuperar o status atual e os detalhes de qualquer pagamento. Passe o `paymentCode` que o Therius devolveu quando o pagamento foi criado (p. ex. `PC-1234567890`) ou o UUID de pagamento interno. Este endpoint é útil para fazer polling de pagamentos pendentes, conciliação e depuração.

<SchemaLangNote lang="pt" />

<Note>
  Diferente das respostas de pagamento/assinatura no resto desta API, `amount` aqui é um inteiro simples nas unidades menores da moeda, com um campo `currency` separado no nível superior — não um objeto `{ currency, value, exponent }`.
</Note>

### Buscar um pagamento recusado

```bash
curl https://api.therius.io/v1/payment/inquiry/PC-9876543210 \
  -H "Authorization: Bearer prv_production_your_key_here"
```

```json
{
  "id": "f9e8d7c6-b5a4-3210-fedc-ba9876543210",
  "status": "declined",
  "paymentCode": "PC-9876543210",
  "orderCode": "ORDER-20240101-003",
  "amount": { "currency": "USD", "value": 2500, "exponent": 2 },
  "currency": "USD",
  "merchantId": "MERCHANT_001",
  "refusalCode": {
    "reason": "Do not honor",
    "reasonCode": "DO_NOT_HONOR",
    "recoveryAction": "switch_method"
  }
}
```

### Consultar o sandbox sem uma chave de API

```bash
curl https://api-sandbox.therius.io/v1/payment/inquiry/PC-1234567890 \
  -H "X-Environment: sandbox"
```

<Note>
  Se não existir nenhum pagamento para o `id` fornecido, a API devolve `404 Not Found`. Verifique o `paymentCode` ou o UUID e certifique-se de que você está consultando o ambiente correto (produção vs. sandbox).
</Note>

<Tip>
  Você pode usar este endpoint para fazer polling do status final de pagamentos `pending_3ds` ou `pending_action` se você preferir não usar webhooks. No entanto, os webhooks são recomendados para produção — eles empurram o status final para o seu servidor assim que ele está disponível, sem exigir polling.
</Tip>
