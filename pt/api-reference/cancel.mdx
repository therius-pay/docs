`POST /payment/{id}/cancel` anula uma autorização antes de ela ser capturada, liberando de imediato a retenção sobre os fundos do titular do cartão. Use isto quando um pedido é cancelado ou não pode ser cumprido depois que a autorização foi colocada. Se o pagamento já foi capturado e liquidado, use [Refund](/api-reference/refund) em vez disso — você não pode cancelar um pagamento capturado.

<SchemaLangNote lang="pt" />

## Identificar o pagamento

`{id}` é o `id` de pagamento do Therius devolvido por `POST /payment/authorization` e `POST /payment/purchase`. `orderCode` e `paymentCode` são os seus próprios campos de referência e **não** são aceitos aqui. Um `id` desconhecido ou não pertencente devolve `404`.

## Requisição

**Endpoint:** `POST https://api.therius.io/v1/payment/{id}/cancel`

### Parâmetros de caminho

<ParamField path="id" type="string" required>
  O `id` de pagamento do Therius da resposta de autorização/purchase.
</ParamField>

### Headers

<ParamField header="Authorization" type="string">
  A sua chave de API secreta como token Bearer: `Bearer sk_live_xxx` (produção) ou `Bearer sk_sandbox_xxx` (sandbox).
</ParamField>

<ParamField header="Idempotency-Key" type="string">
  Um UUID que você gera por operação. Obrigatório em produção para prevenir tentativas de cancelamento duplicadas.
</ParamField>

<ParamField header="Content-Type" type="string" required>
  Deve ser `application/json`.
</ParamField>

### Corpo da requisição

<ParamField body="merchantCode" type="string" required>
  O seu identificador de lojista.
</ParamField>

<ParamField body="reference" type="string">
  Uma referência interna opcional para este cancelamento (p. ex. o seu ID de cancelamento ou de ticket de suporte).
</ParamField>

## Resposta

<ResponseField name="id" type="string">
  O `id` de pagamento do Therius (o mesmo valor que o segmento de caminho `{id}`).
</ResponseField>

<ResponseField name="status" type="string">
  Resultado do cancelamento. Um de:

  - `"cancelled"` — autorização anulada e retenção liberada.
  - `"failed"` — o cancelamento não pôde ser processado. A autorização pode já ter expirado ou sido capturada.
</ResponseField>

<ResponseField name="paymentCode" type="string">
  O ID de recibo do Therius para o pagamento original.
</ResponseField>

<ResponseField name="orderCode" type="string">
  O seu `orderCode` original.
</ResponseField>

<ResponseField name="merchantCode" type="string">
  O seu `merchantCode`.
</ResponseField>

<ResponseField name="amount" type="object">
  O valor que estava retido e que agora é liberado, em formato `{ currency, value, exponent }`.
</ResponseField>

## Exemplo

### Cancelar uma autorização

<RequestExample>

```bash cURL
curl -X POST https://api.therius.io/v1/payment/9f8b2c1e-4d5a-6b7c-8d9e-0f1a2b3c4d5e/cancel \
  -H "Authorization: Bearer sk_live_your_key_here" \
  -H "Idempotency-Key: $(uuidgen)" \
  -H "Content-Type: application/json" \
  -d '{
    "merchantCode": "MERCHANT_001"
  }'
```

</RequestExample>

<ResponseExample>

```json 200 OK
{
  "id": "9f8b2c1e-4d5a-6b7c-8d9e-0f1a2b3c4d5e",
  "status": "cancelled",
  "paymentCode": "PC-1234567890",
  "orderCode": "ORDER-20240101-002",
  "merchantCode": "MERCHANT_001",
  "amount": { "currency": "USD", "value": 9900, "exponent": 2 }
}
```

</ResponseExample>

<Warning>
  Este endpoint só funciona para pagamentos no estado `authorized`. Se o pagamento já foi capturado, esta chamada devolve um erro. Use [Refund](/api-reference/refund) para devolver fundos em um pagamento capturado, ou [Cancel or Refund](/api-reference/cancel-or-refund) se você não conhece o estado atual.
</Warning>

<Note>
  Quando você cancela uma autorização, o saldo disponível do titular do cartão é restaurado de imediato do lado do Therius. O tempo refletido no extrato bancário do titular do cartão varia conforme o emissor — normalmente é de instantâneo a algumas horas, mas pode levar de 3 a 5 dias úteis para alguns emissores.
</Note>
