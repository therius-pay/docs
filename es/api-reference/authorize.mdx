`POST /payment/authorization` reserva fondos en la cuenta del titular de la tarjeta sin liquidarlos. La retención de autorización suele ser válida durante 7 días, aunque la ventana exacta depende del adquirente y de la red de tarjetas. Llama a [Capture](/api-reference/capture) para liquidar los fondos cuando estés listo para cumplir, o a [Cancel](/api-reference/cancel) para liberar la retención si no puedes cumplir el pedido.

<SchemaLangNote lang="es" />

## Solicitud

**Endpoint:** `POST https://api.therius.io/v1/payment/authorization`

### Headers

<ParamField header="Authorization" type="string">
  Tu clave de API secreta como token Bearer: `Bearer prv_production_xxx` (producción) o `Bearer prv_sandbox_xxx` (sandbox).
</ParamField>

<ParamField header="Idempotency-Key" type="string">
  Un UUID que generas por operación. Requerido en producción. Reintentar con la misma clave devuelve la respuesta original sin crear una retención duplicada.
</ParamField>

<ParamField header="Content-Type" type="string" required>
  Debe ser `application/json`.
</ParamField>

### Cuerpo de la solicitud

<ParamField body="merchantCode" type="string" required>
  Tu identificador de comercio, emitido cuando se crea tu cuenta.
</ParamField>

<ParamField body="orderCode" type="string" required>
  Tu referencia de pedido interna. Debe ser única por comercio.
</ParamField>

<ParamField body="amount" type="object" required>
  El monto a reservar.

  <Expandable title="campos de amount">
    <ParamField body="currency" type="string" required>
      Código de moneda ISO 4217, p. ej. `"USD"`, `"EUR"`, `"JPY"`.
    </ParamField>

    <ParamField body="value" type="integer" required>
      Monto en unidades menores. Para USD, `4999` = \$49.99. Para JPY, `5000` = ¥5000.
    </ParamField>

    <ParamField body="exponent" type="integer" required>
      Número de decimales de la moneda. `2` para USD/EUR, `0` para JPY.
    </ParamField>
  </Expandable>
</ParamField>

<ParamField body="card" type="object">
  Datos de pago con tarjeta. Proporciona exactamente uno de `cardData`, `nonceData` o `tokenData`. Omite este campo al usar un APM. Ver la referencia de [Purchase](/api-reference/purchase) para el esquema completo de `card`.

  <Expandable title="campos de card">
    <ParamField body="cardData" type="object">
      Datos de tarjeta sin procesar (`cardNumber`, `cardholderName`, `expiryMonth`, `expiryYear`, `cvv`, `tokenize`, `cardAddress`, `documentNumber`, `typeOverride`).
    </ParamField>

    <ParamField body="nonceData" type="object">
      Nonce generado por el SDK (`nonce`, `cardholderName`, `cardAddress`, `tokenize`, `typeOverride`).
    </ParamField>

    <ParamField body="tokenData" type="object">
      Token guardado (`token`, `cvv`, `cardAddress`).
    </ParamField>

    <ParamField body="instalments" type="integer">
      Número de cuotas, si el adquirente lo soporta.
    </ParamField>

    <ParamField body="networkTransactionId" type="string">
      ID de transacción de red original para flujos MIT.
    </ParamField>

    <ParamField body="networkReferenceId" type="string">
      ID de referencia de red original para flujos recurrentes.
    </ParamField>
  </Expandable>
</ParamField>

<ParamField body="apm" type="object">
  Datos del método de pago alternativo. Úsalo en lugar de `card` para APM. La estructura varía según el método de pago.
</ParamField>

<ParamField body="paymentMethod" type="string">
  Código del método de pago. Omítelo para pagos con tarjeta. Para APM, usa `"pix"`, `"ach"`, etc.
</ParamField>

<ParamField body="shopper" type="object">
  Información del comprador. Requerida al tokenizar.

  <Expandable title="campos de shopper">
    <ParamField body="id" type="string">
      Tu ID de comprador interno.
    </ParamField>

    <ParamField body="email" type="string">
      Dirección de correo del comprador.
    </ParamField>

    <ParamField body="name" type="string">
      Nombre completo del comprador.
    </ParamField>
  </Expandable>
</ParamField>

<ParamField body="webhookUrl" type="string">
  Anulación de la URL de webhook por pago (solo HTTPS).
</ParamField>

<ParamField body="connectionCode" type="string">
  Fija este pago a una conexión de gateway específica.
</ParamField>

<ParamField body="ipAddress" type="string">
  Dirección IP del titular de la tarjeta para scoring de fraude.
</ParamField>

<ParamField body="metadata" type="object">
  Pares clave/valor string arbitrarios, devueltos en los webhooks.
</ParamField>

## Respuesta

<ResponseField name="id" type="string">
  El `id` de pago de Therius (un UUID). **Guárdalo** — es el identificador del pago: pásalo como el segmento de ruta `{id}` de tu llamada posterior a [Capture](/api-reference/capture), [Cancel](/api-reference/cancel), [Refund](/api-reference/refund) o [Cancel or Refund](/api-reference/cancel-or-refund).
</ResponseField>

<ResponseField name="status" type="string">
  Resultado de la autorización. Uno de:

  - `"authorized"` — los fondos están reservados con éxito. Llama a [Capture](/api-reference/capture) para liquidar.
  - `"declined"` — el emisor rechazó. Revisa `refusalCode`.
  - `"pending_3ds"` — el titular de la tarjeta debe completar un desafío 3DS. Revisa `actionRequired`.
  - `"pending_action"` — el pago requiere una acción externa. Revisa `actionRequired`.
  - `"failed"` — error de procesamiento.
</ResponseField>

<ResponseField name="paymentCode" type="string">
  El ID de recibo de Therius (p. ej. `"PC-1234567890"`). Es una referencia para conciliación y soporte — **no** se usa para direccionar el pago para captura/cancelación/reembolso; usa `id` para eso.
</ResponseField>

<ResponseField name="orderCode" type="string">
  Tu `orderCode`, devuelto.
</ResponseField>

<ResponseField name="merchantCode" type="string">
  Tu `merchantCode`, devuelto.
</ResponseField>

<ResponseField name="amount" type="object">
  El monto reservado en formato `{ currency, value, exponent }`.
</ResponseField>

<ResponseField name="card" type="object">
  Respuesta de tarjeta incluyendo el PAN enmascarado, la bandera, el tipo y los IDs de transacción de red.
</ResponseField>

<ResponseField name="token" type="object">
  Presente si se solicitó `tokenize: true`. Contiene `id` y `expirationDate`.
</ResponseField>

<ResponseField name="actionRequired" type="object">
  Presente cuando `status` es `"pending_3ds"` o `"pending_action"`. Contiene `type`, `url`, `paymentCode`, `barcode` y `params`.
</ResponseField>

<ResponseField name="refusalCode" type="object">
  Presente en rechazo. Contiene `reason`, `reasonCode`, `originalReason`, `originalReasonCode` y `recoveryAction` (`"retry"`, `"switch_method"` o `"terminal"`).
</ResponseField>

<Note>
  Se soporta la captura parcial. Cuando llamas a [Capture](/api-reference/capture), puedes pasar un `amount` menor o igual al monto autorizado. Por ejemplo, si autorizaste $$99.00 pero solo enviaste $$75.00 en bienes, captura \$75.00 y la retención restante se libera automáticamente.
</Note>

<Warning>
  Las retenciones de autorización expiran — normalmente después de 7 días, pero esto varía según el adquirente y la red de tarjetas. Si no llamas a [Capture](/api-reference/capture) antes del vencimiento, la retención se libera y necesitarás volver a autorizar. Monitorea la antigüedad de la retención en tu sistema de gestión de pedidos.
</Warning>
