`POST /payment/purchase` autoriza y captura fondos en un solo ida y vuelta. Úsalo cuando puedes cumplir el pedido de inmediato — bienes digitales, suscripciones SaaS o retail con stock. Para bienes físicos que se envían más tarde, considera [Authorize](/api-reference/authorize) \+ [Capture](/api-reference/capture) para retener fondos hasta el cumplimiento sin liquidar antes de tiempo.

<SchemaLangNote lang="es" />

## Solicitud

**Endpoint:** `POST https://api.therius.io/v1/payment/purchase`

### Headers

<ParamField header="Authorization" type="string">
  Tu clave de API secreta como token Bearer: `Bearer sk_live_xxx` (producción) o `Bearer sk_sandbox_xxx` (sandbox).
</ParamField>

<ParamField header="Idempotency-Key" type="string">
  Un UUID que generas por operación. Requerido en producción. Reintentar con la misma clave devuelve la respuesta original sin crear un cobro duplicado.
</ParamField>

<ParamField header="Content-Type" type="string" required>
  Debe ser `application/json`.
</ParamField>

### Cuerpo de la solicitud

<ParamField body="merchantCode" type="string" required>
  Tu identificador de comercio, emitido cuando se crea tu cuenta.
</ParamField>

<ParamField body="orderCode" type="string" required>
  Tu referencia de pedido interna. Debe ser única por comercio. Usa este valor para correlacionar los pagos de Therius con tus propios registros de pedidos.
</ParamField>

<ParamField body="amount" type="object" required>
  El monto a cobrar.

  <Expandable title="campos de amount">
    <ParamField body="currency" type="string" required>
      Código de moneda ISO 4217, p. ej. `"USD"`, `"EUR"`, `"JPY"`.
    </ParamField>

    <ParamField body="value" type="integer" required>
      Monto en unidades menores (centavos, peniques, etc.). Para USD, `4999` = \$49.99. Para JPY (sin decimales), `5000` = ¥5000.
    </ParamField>

    <ParamField body="exponent" type="integer" required>
      Número de decimales de la moneda. `2` para USD/EUR, `0` para JPY.
    </ParamField>
  </Expandable>
</ParamField>

<ParamField body="card" type="object">
  Datos de pago con tarjeta. Proporciona exactamente uno de `cardData`, `nonceData` o `tokenData`. Omite este campo al usar un APM.

  <Expandable title="campos de card">
    <ParamField body="cardData" type="object">
      Datos de tarjeta sin procesar. Úsalo solo en entornos que cumplen PCI o vía un iframe seguro.

      <Expandable title="campos de cardData">
        <ParamField body="cardNumber" type="string">
          PAN completo, solo dígitos.
        </ParamField>

        <ParamField body="cardholderName" type="string">
          Nombre tal como aparece en la tarjeta.
        </ParamField>

        <ParamField body="expiryMonth" type="string">
          Mes de vencimiento de dos dígitos, p. ej. `"12"`.
        </ParamField>

        <ParamField body="expiryYear" type="string">
          Año de vencimiento de cuatro dígitos, p. ej. `"2030"`.
        </ParamField>

        <ParamField body="cvv" type="string">
          Valor de verificación de la tarjeta (3 o 4 dígitos).
        </ParamField>

        <ParamField body="tokenize" type="boolean">
          Establece en `true` para guardar esta tarjeta como un token reutilizable. Requiere `shopper.id` en la solicitud.
        </ParamField>

        <ParamField body="cardAddress" type="object">
          Dirección de facturación para verificaciones AVS.
        </ParamField>

        <ParamField body="documentNumber" type="string">
          ID fiscal/de documento del titular de la tarjeta, requerido por algunos adquirentes de LatAm.
        </ParamField>

        <ParamField body="typeOverride" type="string">
          Anula el tipo de tarjeta detectado, p. ej. `"debit"`.
        </ParamField>
      </Expandable>
    </ParamField>

    <ParamField body="nonceData" type="object">
      Nonce generado por el SDK. Úsalo en lugar de `cardData` al recolectar los datos de tarjeta a través del SDK JS de Therius.

      <Expandable title="campos de nonceData">
        <ParamField body="nonce" type="string">
          La cadena de nonce devuelta por el SDK.
        </ParamField>

        <ParamField body="cardholderName" type="string">
          Nombre del titular de la tarjeta.
        </ParamField>

        <ParamField body="cardAddress" type="object">
          Dirección de facturación.
        </ParamField>

        <ParamField body="tokenize" type="boolean">
          Guarda la tarjeta como un token después del pago.
        </ParamField>

        <ParamField body="typeOverride" type="string">
          Anula el tipo de tarjeta detectado.
        </ParamField>
      </Expandable>
    </ParamField>

    <ParamField body="tokenData" type="object">
      Datos de token guardado. Úsalo al cobrar una tarjeta que el comprador tokenizó previamente.

      <Expandable title="campos de tokenData">
        <ParamField body="token" type="string">
          ID de token devuelto de una tokenización anterior.
        </ParamField>

        <ParamField body="cvv" type="string">
          CVV, si el adquirente requiere volver a recolectarlo.
        </ParamField>

        <ParamField body="cardAddress" type="object">
          Anulación de la dirección de facturación.
        </ParamField>
      </Expandable>
    </ParamField>

    <ParamField body="cardOnFile" type="object">
      Indica que esta es una transacción de tarjeta archivada / recurrente. Usada para flujos MIT (iniciados por el comercio).
    </ParamField>

    <ParamField body="instalments" type="integer">
      Número de cuotas. Soportado en adquirentes y banderas de tarjeta seleccionados.
    </ParamField>

    <ParamField body="networkTransactionId" type="string">
      ID de transacción de red original para un MIT recurrente o no programado.
    </ParamField>

    <ParamField body="networkReferenceId" type="string">
      ID de referencia de red original para un MIT recurrente o no programado.
    </ParamField>
  </Expandable>
</ParamField>

<ParamField body="apm" type="object">
  Datos del método de pago alternativo. Úsalo en lugar de `card` para APM como Pix o ACH. La estructura varía según el método de pago.
</ParamField>

<ParamField body="paymentMethod" type="string">
  Código del método de pago. Omítelo para pagos con tarjeta. Para APM, pasa el código relevante — p. ej. `"pix"`, `"ach"`, `"boleto"`.
</ParamField>

<ParamField body="shopper" type="object">
  Información del comprador. Requerida cuando `card.cardData.tokenize` o `card.nonceData.tokenize` es `true`.

  <Expandable title="campos de shopper">
    <ParamField body="id" type="string">
      Tu ID de comprador interno. Usado para asociar tokens con un cliente.
    </ParamField>

    <ParamField body="email" type="string">
      Dirección de correo del comprador.
    </ParamField>

    <ParamField body="name" type="string">
      Nombre completo del comprador.
    </ParamField>
  </Expandable>
</ParamField>

<ParamField body="webhookUrl" type="string">
  Anulación de la URL de webhook por pago. Debe usar HTTPS. Therius hace un post del estado final del pago a esta URL cuando cambia de forma asíncrona.
</ParamField>

<ParamField body="connectionCode" type="string">
  Fija este pago a una conexión de gateway específica. Omítelo para usar tus reglas de enrutamiento por defecto.
</ParamField>

<ParamField body="ipAddress" type="string">
  Dirección IP del titular de la tarjeta. Se pasa a los sistemas de scoring de fraude cuando está disponible.
</ParamField>

<ParamField body="metadata" type="object">
  Pares clave/valor arbitrarios (solo valores string). Devueltos tal cual en las cargas de webhook. Útil para adjuntar tus propios metadatos de pedido.
</ParamField>

## Respuesta

<ResponseField name="id" type="string">
  El `id` de pago de Therius (un UUID). **Guárdalo** — es el identificador del pago: pásalo como el segmento de ruta `{id}` de una llamada posterior a [Refund](/api-reference/refund) o [Cancel or Refund](/api-reference/cancel-or-refund).
</ResponseField>

<ResponseField name="status" type="string">
  Resultado del pago. Uno de:

  - `"captured"` — fondos liquidados con éxito.
  - `"declined"` — el emisor rechazó el pago. Revisa `refusalCode`.
  - `"pending_3ds"` — el titular de la tarjeta debe completar un desafío 3D Secure. Revisa `actionRequired`.
  - `"pending_action"` — el pago requiere una acción externa (p. ej. redirect o código de barras). Revisa `actionRequired`.
  - `"failed"` — error de procesamiento no relacionado con el emisor.
</ResponseField>

<ResponseField name="paymentCode" type="string">
  El ID de recibo de Therius para este pago (p. ej. `"PC-1234567890"`). Una referencia para conciliación, soporte e [Inquiry](/api-reference/inquiry) — **no** se usa para direccionar el pago para reembolso/cancelación; usa `id` para eso.
</ResponseField>

<ResponseField name="orderCode" type="string">
  Tu `orderCode`, devuelto para correlación.
</ResponseField>

<ResponseField name="merchantCode" type="string">
  Tu `merchantCode`, devuelto.
</ResponseField>

<ResponseField name="amount" type="object">
  El monto que se procesó, en la misma forma `{ currency, value, exponent }` que la solicitud.
</ResponseField>

<ResponseField name="card" type="object">
  Datos de tarjeta de la respuesta.

  <Expandable title="campos de respuesta de card">
    <ResponseField name="cardData.brand" type="string">
      Red de la tarjeta, p. ej. `"visa"`, `"mastercard"`, `"amex"`.
    </ResponseField>

    <ResponseField name="cardData.cardNumber" type="string">
      PAN enmascarado, p. ej. `"411111****1111"`.
    </ResponseField>

    <ResponseField name="cardData.type" type="string">
      `"credit"` o `"debit"`.
    </ResponseField>

    <ResponseField name="networkTransactionId" type="string">
      ID de transacción de red, devuelto para su uso en futuras referencias MIT.
    </ResponseField>

    <ResponseField name="networkReferenceId" type="string">
      ID de referencia de red para flujos recurrentes.
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="token" type="object">
  Presente cuando la tarjeta fue tokenizada (`cardData.tokenize: true`).

  <Expandable title="campos de token">
    <ResponseField name="id" type="string">
      ID de token para usar en futuros cobros con `tokenData`.
    </ResponseField>

    <ResponseField name="expirationDate" type="string">
      Fecha de vencimiento del token.
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="actionRequired" type="object">
  Presente cuando `status` es `"pending_3ds"` o `"pending_action"`. Describe lo que el titular de la tarjeta debe hacer a continuación.

  <Expandable title="campos de actionRequired">
    <ResponseField name="type" type="string">
      Tipo de acción, p. ej. `"redirect"`, `"barcode"`.
    </ResponseField>

    <ResponseField name="url" type="string">
      URL a la que redirigir al titular de la tarjeta para 3DS o flujos APM externos.
    </ResponseField>

    <ResponseField name="paymentCode" type="string">
      Código de pago de Therius ligado a esta acción pendiente.
    </ResponseField>

    <ResponseField name="barcode" type="string">
      Valor del código de barras para APM que lo requieren (p. ej. Boleto).
    </ResponseField>

    <ResponseField name="params" type="object">
      Parámetros adicionales requeridos para completar la acción.
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="refusalCode" type="object">
  Presente cuando `status` es `"declined"`.

  <Expandable title="campos de refusalCode">
    <ResponseField name="reason" type="string">
      Razón de rechazo legible.
    </ResponseField>

    <ResponseField name="reasonCode" type="string">
      Código de rechazo legible por máquina.
    </ResponseField>

    <ResponseField name="originalReason" type="string">
      Cadena de razón sin procesar del emisor o adquirente.
    </ResponseField>

    <ResponseField name="originalReasonCode" type="string">
      Código de razón sin procesar del emisor o adquirente.
    </ResponseField>

    <ResponseField name="recoveryAction" type="string">
      Próximo paso sugerido: `"retry"` (volver a intentar), `"switch_method"` (pedir otra tarjeta/método al comprador) o `"terminal"` (no reintentar).
    </ResponseField>
  </Expandable>
</ResponseField>

## Ejemplos

### Cobrar una tarjeta

<RequestExample>

```bash cURL
curl -X POST https://api.therius.io/v1/payment/purchase \
  -H "Authorization: Bearer sk_live_your_key_here" \
  -H "Idempotency-Key: $(uuidgen)" \
  -H "Content-Type: application/json" \
  -d '{
    "merchantCode": "MERCHANT_001",
    "orderCode": "ORDER-20240101-001",
    "amount": { "currency": "USD", "value": 4999, "exponent": 2 },
    "card": {
      "cardData": {
        "cardNumber": "4111111111111111",
        "cardholderName": "Ada Lovelace",
        "expiryMonth": "12",
        "expiryYear": "2030",
        "cvv": "123"
      }
    }
  }'
```

</RequestExample>

<ResponseExample>

```json 200 OK
{
  "id": "9f8b2c1e-4d5a-6b7c-8d9e-0f1a2b3c4d5e",
  "status": "captured",
  "paymentCode": "PC-1234567890",
  "orderCode": "ORDER-20240101-001",
  "merchantCode": "MERCHANT_001",
  "amount": { "currency": "USD", "value": 4999, "exponent": 2 },
  "card": {
    "cardData": { "brand": "visa", "cardNumber": "411111****1111", "type": "credit" },
    "networkTransactionId": "txn_abc123"
  }
}
```

</ResponseExample>

**Respuesta rechazada**

```json
{
  "status": "declined",
  "paymentCode": "PC-9876543210",
  "orderCode": "ORDER-20240101-002",
  "merchantCode": "MERCHANT_001",
  "amount": { "currency": "USD", "value": 4999, "exponent": 2 },
  "refusalCode": {
    "reason": "Insufficient funds",
    "reasonCode": "INSUFFICIENT_FUNDS",
    "recoveryAction": "switch_method"
  }
}
```

<Note>
  `amount.value` siempre está en unidades menores. `1999` = \$19.99 para USD (exponent `2`). `5000` = ¥5000 para JPY (exponent `0`). Usa siempre el campo `exponent` para determinar la posición decimal.
</Note>

<Note>
  Si `status` es `"pending_3ds"`, redirige al titular de la tarjeta a `actionRequired.url` para completar el desafío 3D Secure. Una vez que termina, llama a [POST /payment/resume](/api-reference/resume) con el `sessionId` de la respuesta `pending_3ds` para continuar. Si usas el SDK JS de Therius, llama a `sdk.handleAction(result.actionRequired)` — maneja el redirect y el resume automáticamente.
</Note>
