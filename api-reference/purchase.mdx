`POST /payment/purchase` authorizes and captures funds in a single round-trip. Use it when you can fulfill the order immediately — digital goods, SaaS subscriptions, or in-stock retail. For physical goods that ship later, consider [Authorize](/api-reference/authorize) \+ [Capture](/api-reference/capture) to hold funds until fulfillment without settling early.

## Request

**Endpoint:** `POST https://api.therius.io/v1/payment/purchase`

<ParamField header="Authorization" type="string">
  Your secret API key as a Bearer token: `Bearer sk_live_xxx` (production) or `Bearer sk_sandbox_xxx` (sandbox). Required unless you pass `key` in the request body.
</ParamField>

<ParamField header="Idempotency-Key" type="string">
  A UUID you generate per operation. Required in production. Retrying with the same key returns the original response without creating a duplicate charge.
</ParamField>

<ParamField header="Content-Type" type="string" required>
  Must be `application/json`.
</ParamField>

<ParamField body="key" type="string">
  Your merchant private API key. You can pass this in the body instead of the `Authorization` header, but the header is preferred.
</ParamField>

<ParamField body="merchantCode" type="string" required>
  Your merchant identifier, issued when your account is created.
</ParamField>

<ParamField body="orderCode" type="string" required>
  Your internal order reference. Must be unique per merchant. Use this value to correlate Therius payments with your own order records.
</ParamField>

<ParamField body="amount" type="object" required>
  The amount to charge.

  <Expandable title="amount fields">
    <ParamField body="currency" type="string" required>
      ISO 4217 currency code, e.g. `"USD"`, `"EUR"`, `"JPY"`.
    </ParamField>

    <ParamField body="value" type="integer" required>
      Amount in minor units (cents, pence, etc.). For USD, `4999` = \$49.99. For JPY (zero-decimal), `5000` = ¥5000.
    </ParamField>

    <ParamField body="exponent" type="integer" required>
      Number of decimal places for the currency. `2` for USD/EUR, `0` for JPY.
    </ParamField>
  </Expandable>
</ParamField>

<ParamField body="card" type="object">
  Card payment data. Provide exactly one of `cardData`, `nonceData`, or `tokenData`. Omit this field when using an APM.

  <Expandable title="card fields">
    <ParamField body="cardData" type="object">
      Raw card details. Use only in PCI-compliant environments or via a secure iframe.

      <Expandable title="cardData fields">
        <ParamField body="cardNumber" type="string">
          Full PAN, digits only.
        </ParamField>

        <ParamField body="cardholderName" type="string">
          Name as it appears on the card.
        </ParamField>

        <ParamField body="expiryMonth" type="string">
          Two-digit expiry month, e.g. `"12"`.
        </ParamField>

        <ParamField body="expiryYear" type="string">
          Four-digit expiry year, e.g. `"2030"`.
        </ParamField>

        <ParamField body="cvv" type="string">
          Card verification value (3 or 4 digits).
        </ParamField>

        <ParamField body="tokenize" type="boolean">
          Set to `true` to save this card as a reusable token. Requires `shopper.id` in the request.
        </ParamField>

        <ParamField body="cardAddress" type="object">
          Billing address for AVS checks.
        </ParamField>

        <ParamField body="documentNumber" type="string">
          Cardholder tax/document ID, required by some LatAm acquirers.
        </ParamField>

        <ParamField body="typeOverride" type="string">
          Override the detected card type, e.g. `"debit"`.
        </ParamField>
      </Expandable>
    </ParamField>

    <ParamField body="nonceData" type="object">
      SDK-generated nonce. Use this instead of `cardData` when collecting card details through the Therius JS SDK.

      <Expandable title="nonceData fields">
        <ParamField body="nonce" type="string">
          The nonce string returned by the SDK.
        </ParamField>

        <ParamField body="cardholderName" type="string">
          Cardholder name.
        </ParamField>

        <ParamField body="cardAddress" type="object">
          Billing address.
        </ParamField>

        <ParamField body="tokenize" type="boolean">
          Save the card as a token after payment.
        </ParamField>

        <ParamField body="typeOverride" type="string">
          Override detected card type.
        </ParamField>
      </Expandable>
    </ParamField>

    <ParamField body="tokenData" type="object">
      Saved-token data. Use when charging a card the shopper previously tokenized.

      <Expandable title="tokenData fields">
        <ParamField body="token" type="string">
          Token ID returned from a prior tokenization.
        </ParamField>

        <ParamField body="cvv" type="string">
          CVV, if re-collection is required by the acquirer.
        </ParamField>

        <ParamField body="cardAddress" type="object">
          Billing address override.
        </ParamField>
      </Expandable>
    </ParamField>

    <ParamField body="cardOnFile" type="object">
      Indicates this is a card-on-file / recurring transaction. Used for MIT (merchant-initiated) flows.
    </ParamField>

    <ParamField body="instalments" type="integer">
      Number of instalments. Supported on select acquirers and card brands.
    </ParamField>

    <ParamField body="networkTransactionId" type="string">
      Original network transaction ID for a recurring or unscheduled MIT.
    </ParamField>

    <ParamField body="networkReferenceId" type="string">
      Original network reference ID for a recurring or unscheduled MIT.
    </ParamField>
  </Expandable>
</ParamField>

<ParamField body="apm" type="object">
  Alternative payment method data. Use this instead of `card` for APMs such as Pix or ACH. Structure varies by payment method.
</ParamField>

<ParamField body="paymentMethod" type="string">
  Payment method code. Omit for card payments. For APMs, pass the relevant code — e.g. `"pix"`, `"ach"`, `"boleto"`.
</ParamField>

<ParamField body="shopper" type="object">
  Shopper information. Required when `card.cardData.tokenize` or `card.nonceData.tokenize` is `true`.

  <Expandable title="shopper fields">
    <ParamField body="id" type="string">
      Your internal shopper ID. Used to associate tokens with a customer.
    </ParamField>

    <ParamField body="email" type="string">
      Shopper's email address.
    </ParamField>

    <ParamField body="name" type="string">
      Shopper's full name.
    </ParamField>
  </Expandable>
</ParamField>

<ParamField body="webhookUrl" type="string">
  Per-payment webhook URL override. Must use HTTPS. Therius posts the final payment status to this URL when it changes asynchronously.
</ParamField>

<ParamField body="connectionCode" type="string">
  Pin this payment to a specific gateway connection. Omit to use your default routing rules.
</ParamField>

<ParamField body="ipAddress" type="string">
  Cardholder's IP address. Passed to fraud-scoring systems when available.
</ParamField>

<ParamField body="metadata" type="object">
  Arbitrary key/value pairs (string values only). Returned as-is in webhook payloads. Useful for attaching your own order metadata.
</ParamField>

## Response

<ResponseField name="status" type="string">
  Payment outcome. One of:

  - `"captured"` — funds settled successfully.
  - `"declined"` — issuer declined the payment. Check `refusalCode`.
  - `"pending_3ds"` — cardholder must complete a 3D Secure challenge. Check `actionRequired`.
  - `"pending_action"` — payment requires an external action (e.g. redirect or barcode). Check `actionRequired`.
  - `"failed"` — processing error unrelated to the issuer.
</ResponseField>

<ResponseField name="paymentCode" type="string">
  Therius's unique receipt ID for this payment (e.g. `"PC-1234567890"`). Save this — you'll need it for captures, refunds, and inquiries.
</ResponseField>

<ResponseField name="orderCode" type="string">
  Your `orderCode`, echoed back for correlation.
</ResponseField>

<ResponseField name="merchantCode" type="string">
  Your `merchantCode`, echoed back.
</ResponseField>

<ResponseField name="amount" type="object">
  The amount that was processed, in the same `{ currency, value, exponent }` shape as the request.
</ResponseField>

<ResponseField name="card" type="object">
  Card details from the response.

  <Expandable title="card response fields">
    <ResponseField name="cardData.brand" type="string">
      Card network, e.g. `"visa"`, `"mastercard"`, `"amex"`.
    </ResponseField>

    <ResponseField name="cardData.cardNumber" type="string">
      Masked PAN, e.g. `"411111****1111"`.
    </ResponseField>

    <ResponseField name="cardData.type" type="string">
      `"credit"` or `"debit"`.
    </ResponseField>

    <ResponseField name="networkTransactionId" type="string">
      Network transaction ID, returned for use in future MIT references.
    </ResponseField>

    <ResponseField name="networkReferenceId" type="string">
      Network reference ID for recurring flows.
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="token" type="object">
  Present when the card was tokenized (`cardData.tokenize: true`).

  <Expandable title="token fields">
    <ResponseField name="id" type="string">
      Token ID to use in future `tokenData` charges.
    </ResponseField>

    <ResponseField name="expirationDate" type="string">
      Token expiry date.
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="actionRequired" type="object">
  Present when `status` is `"pending_3ds"` or `"pending_action"`. Describes what the cardholder must do next.

  <Expandable title="actionRequired fields">
    <ResponseField name="type" type="string">
      Action type, e.g. `"redirect"`, `"barcode"`.
    </ResponseField>

    <ResponseField name="url" type="string">
      URL to redirect the cardholder to for 3DS or external APM flows.
    </ResponseField>

    <ResponseField name="paymentCode" type="string">
      Therius payment code tied to this pending action.
    </ResponseField>

    <ResponseField name="barcode" type="string">
      Barcode value for APMs that require it (e.g. Boleto).
    </ResponseField>

    <ResponseField name="params" type="object">
      Additional parameters required to complete the action.
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="refusalCode" type="object">
  Present when `status` is `"declined"`.

  <Expandable title="refusalCode fields">
    <ResponseField name="reason" type="string">
      Human-readable decline reason.
    </ResponseField>

    <ResponseField name="reasonCode" type="string">
      Machine-readable decline code.
    </ResponseField>

    <ResponseField name="originalReason" type="string">
      Raw reason string from the issuer or acquirer.
    </ResponseField>

    <ResponseField name="originalReasonCode" type="string">
      Raw reason code from the issuer or acquirer.
    </ResponseField>

    <ResponseField name="recoveryAction" type="string">
      Suggested next step: `"retry"` (try again), `"switch_method"` (ask shopper for another card/method), or `"terminal"` (do not retry).
    </ResponseField>
  </Expandable>
</ResponseField>

## Examples

### Charge a card

<RequestExample>

```bash cURL
curl -X POST https://api.therius.io/v1/payment/purchase \
  -H "Authorization: Bearer sk_live_your_key_here" \
  -H "Idempotency-Key: $(uuidgen)" \
  -H "Content-Type: application/json" \
  -d '{
    "merchantCode": "MERCHANT_001",
    "orderCode": "ORDER-20240101-001",
    "amount": { "currency": "USD", "value": 4999, "exponent": 2 },
    "card": {
      "cardData": {
        "cardNumber": "4111111111111111",
        "cardholderName": "Ada Lovelace",
        "expiryMonth": "12",
        "expiryYear": "2030",
        "cvv": "123"
      }
    }
  }'
```

</RequestExample>

<ResponseExample>

```json 200 OK
{
  "status": "captured",
  "paymentCode": "PC-1234567890",
  "orderCode": "ORDER-20240101-001",
  "merchantCode": "MERCHANT_001",
  "amount": { "currency": "USD", "value": 4999, "exponent": 2 },
  "card": {
    "cardData": { "brand": "visa", "cardNumber": "411111****1111", "type": "credit" },
    "networkTransactionId": "txn_abc123"
  }
}
```

</ResponseExample>

**Declined response**

```json
{
  "status": "declined",
  "paymentCode": "PC-9876543210",
  "orderCode": "ORDER-20240101-002",
  "merchantCode": "MERCHANT_001",
  "amount": { "currency": "USD", "value": 4999, "exponent": 2 },
  "refusalCode": {
    "reason": "Insufficient funds",
    "reasonCode": "INSUFFICIENT_FUNDS",
    "recoveryAction": "switch_method"
  }
}
```

<Note>
  `amount.value` is always in minor units. `1999` = \$19.99 for USD (exponent `2`). `5000` = ¥5000 for JPY (exponent `0`). Always use the `exponent` field to determine the decimal position.
</Note>

<Note>
  If `status` is `"pending_3ds"`, redirect the cardholder to `actionRequired.url` to complete the 3D Secure challenge. Once they finish, call [POST /payment/resume](/api-reference/resume) with the `sessionId` from the `pending_3ds` response to continue. If you use the Therius JS SDK, call `sdk.handleAction(result.actionRequired)` — it handles the redirect and resume automatically.
</Note>
