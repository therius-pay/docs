---
title: "Update a Subscription's Payment Method"
sidebarTitle: "Update Card on File"
description: "Replace the card on a subscription with a new CIT. Also reactivates a suspended subscription."
openapi: "POST /subscription/{id}/payment-method"
---

`POST /subscription/{id}/payment-method` replaces the card on a subscription and establishes a new Cardholder Initiated Transaction (CIT) mandate. This is also the only way to reactivate a `suspended` subscription — one where dunning retries have been exhausted and billing has stopped entirely.

Supply the new card as **exactly one** of three interchangeable instruments — a fresh SDK nonce (`nonceData`), raw card data (`cardData`, PCI DSS compliant servers only), or a stored vault token (`tokenData`). This call performs a new CIT, so the customer must have been present and consenting to recurring billing when you collected the card.

<Warning>
  Do not send stored-credential fields (`cardOnFile`, `networkTransactionId`, `networkReferenceId`) or `instalments` here — they are ignored. Therius owns the new mandate and drives every subsequent renewal as an MIT itself.
</Warning>

## Request

**Base URL:** `https://api.therius.io/v1`

**Endpoint:** `POST /subscription/{id}/payment-method`

**Authentication:** `Authorization: Bearer sk_live_xxx` header, or pass `key` in the request body.

**Idempotency:** You may pass an `Idempotency-Key` header.

### Path Parameters

<ParamField path="id" type="string" required>
  The UUID of the subscription to update.
</ParamField>

### Request Body

<ParamField body="key" type="string">
  Your private API key.
</ParamField>

<ParamField body="merchantCode" type="string">
  Your merchant account identifier.
</ParamField>

<ParamField body="card" type="object" required>
  The new card. Provide **exactly one** of the instruments below — they are interchangeable alternatives, not fields to combine.

  <Expandable title="card instruments — choose one">
    <ParamField body="card.nonceData.nonce" type="string">
      A fresh single-use nonce from the Therius JS SDK. Recommended — no card data touches your server.
    </ParamField>
    <ParamField body="card.cardData" type="object">
      Raw card fields — `cardNumber`, `expiryMonth`, `expiryYear`, `cvv`, `cardholderName` (and optional `documentNumber`, `cardAddress`). Only if your server is PCI DSS compliant to handle raw PANs.
    </ParamField>
    <ParamField body="card.tokenData.token" type="string">
      A stored `vt_...` vault token.
    </ParamField>
  </Expandable>
</ParamField>

## Response

Returns `200 OK` with the updated subscription object. The response includes the new masked card details under `paymentMethod`.

### Webhook events fired

| Event | When |
| --- | --- |
| `subscription.payment_method_updated` | Always, on success. |
| `subscription.reactivated` | Additionally fired if the subscription was `suspended` and the new CIT succeeded. |

## Errors

| Code | Meaning |
| --- | --- |
| `404` | Subscription not found. |
| `422` | No card instrument provided, an expired/used nonce, or the CIT was declined by the card network. |

<RequestExample>

```bash cURL
curl -X POST https://api.therius.io/v1/subscription/sub_abc123def456/payment-method \
  -H "Authorization: Bearer sk_live_your_key_here" \
  -H "Content-Type: application/json" \
  -d '{
    "merchantCode": "MERCHANT_001",
    "card": {
      "nonceData": {
        "nonce": "<fresh nonce from JS SDK>"
      }
    }
  }'
```

</RequestExample>

<ResponseExample>

```json 200 OK
{}
```

</ResponseExample>

<Tip>
  Build a card-update flow in your customer portal by creating a new SDK session (`POST /sdk/session`) server-side, passing the `clientToken` to the browser, collecting the new card via the JS SDK, and then calling this endpoint with the resulting nonce.
</Tip>
