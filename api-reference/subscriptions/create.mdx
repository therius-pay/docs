`POST /subscription` enrolls a customer in a plan and establishes the recurring mandate that
anchors every future Merchant Initiated Transaction (MIT). Enrolling a customer is a
Cardholder Initiated Transaction (CIT), and a CIT may require 3D Secure. Two modes:

<CardGroup cols={2}>
  <Card title="CIT mode — nonceData / cardData" icon="credit-card">
    Therius runs the initial CIT + first charge here. The customer must be present. This CIT
    **cannot carry out a 3D Secure challenge** — a 3DS-required card will fail.
  </Card>
  <Card title="Record mode — tokenData" icon="shield-check">
    The token is a card that **already completed a CIT** (including 3DS) through
    `/payment/authorization` or `/payment/purchase`. No second CIT runs here.
    **Use this for any card that needs 3D Secure.**
  </Card>
</CardGroup>

Supply the card as **exactly one** instrument — `nonceData`, `cardData` (PCI DSS compliant
servers only), or `tokenData`.

<Warning>
  `cardOnFile` and `instalments` are ignored here — Therius owns the mandate. In record mode
  `networkTransactionId` / `networkReferenceId` are read from the token; pass them only for a
  card CIT'd outside Therius.
</Warning>

## Record mode

Run a 3DS-capable CIT yourself, then attach the result:

<Steps>
  <Step title="Run the CIT via /payment/*">
    Call `/payment/authorization` (amount 0 = account verification) or `/payment/purchase`
    with `card.<x>.tokenize: true` + a `shopper.id`, and handle any 3DS challenge with the
    JS SDK as you would for a normal payment. The response returns a `vt_...` token.
  </Step>
  <Step title="Create the subscription">
    `POST /subscription` with `card.tokenData.token`. For cycle 1:
    <br />• trial or deferred `startAt` → nothing is charged;
    <br />• you charged the first cycle in your CIT (`/payment/purchase`) → also pass
    `firstPaymentId` (the payment `id` from that call's response); Therius marks the first
    invoice paid and links it, no charge;
    <br />• your CIT was a zero-value verification → omit `firstPaymentId`; Therius charges
    cycle 1 as an MIT against the recorded mandate (rolls the subscription back with a `402`
    if it declines).
    <br />The response's `firstCycle` object reports what happened.
  </Step>
</Steps>

## Request

**Base URL:** `https://api.therius.io/v1`

**Endpoint:** `POST /subscription`

### Headers

<ParamField header="Authorization" type="string" required>
  `Bearer sk_live_xxx` (production) or `Bearer sk_sandbox_xxx` (sandbox) — your merchant private API key.
</ParamField>

<ParamField header="Content-Type" type="string" required>
  `application/json`
</ParamField>

<ParamField header="Idempotency-Key" type="string">
  A UUID you generate per operation. Retrying with the same key returns the original response instead of repeating the operation. Recommended in production.
</ParamField>

### Request Body

<ParamField body="merchantCode" type="string" required>
  Your unique merchant account identifier.
</ParamField>

<ParamField body="planId" type="integer" required>
  The ID of an active billing plan. The plan determines the amount, currency, interval, and trial configuration.
</ParamField>

<ParamField body="customerEmail" type="string">
  Customer's email address. Used for billing notifications and dunning communications.
</ParamField>

<ParamField body="customerName" type="string">
  Customer's full name as it should appear on invoices.
</ParamField>

<ParamField body="customerDocument" type="string">
  Customer's national ID or tax document number. Required in some countries (e.g. Brazil CPF/CNPJ). Check the plan's `availableCountries` configuration for local requirements.
</ParamField>

<ParamField body="card" type="object" required>
  Card details for the initial CIT. Provide **exactly one** of the instruments below — they are interchangeable alternatives, not fields to combine.

  <Expandable title="card instruments — choose one">
    <ParamField body="card.nonceData.nonce" type="string">
      A fresh single-use nonce from the Therius JS SDK. Recommended — no card data touches your server. Nonces are single-use and expire after a short window.
    </ParamField>
    <ParamField body="card.cardData" type="object">
      Raw card fields — `cardNumber`, `expiryMonth`, `expiryYear`, `cvv`, `cardholderName` (and optional `documentNumber`, `cardAddress`). Only if your server is PCI DSS compliant to handle raw PANs.
    </ParamField>
    <ParamField body="card.tokenData.token" type="string">
      **Record mode.** A `vt_...` vault token for a card that already completed its CIT.
    </ParamField>
  </Expandable>
</ParamField>

<ParamField body="firstPaymentId" type="string">
  Record mode only, and only when a first payment is due (ignored for trial or deferred
  subscriptions). The payment `id` returned by the `/payment/authorization` or
  `/payment/purchase` call in which you ran the CIT for this card. Therius validates that it
  is a `captured` or `authorized` payment on your account that charged the **same vaulted
  token** and is in the **plan's currency**, then marks cycle 1's invoice paid and links it
  — no charge. When omitted, Therius charges cycle 1 as an MIT against the recorded mandate.
</ParamField>

<ParamField body="metadata" type="object">
  Arbitrary key/value pairs you want to attach to the subscription. Values must be strings. Returned in all subscription responses and webhook payloads.
</ParamField>

<ParamField body="startAt" type="string">
  RFC 3339 timestamp for a future date to delay the first charge, e.g. `"2025-09-01T00:00:00Z"`. If omitted, the subscription activates and is charged immediately (or at the end of a trial if the plan has one).
</ParamField>

<ParamField body="parentSubscriptionId" type="string">
  UUID of an existing subscription to designate as the parent. Used to model subscription hierarchies (e.g. a base plan and add-ons).
</ParamField>

<ParamField body="propagateLifecycle" type="boolean">
  When `true`, pause and cancel events on the parent subscription automatically cascade to this child subscription. Requires `parentSubscriptionId`.
</ParamField>

## Response

A successful request returns `201 Created` with the full subscription object, including the subscription `id`, initial `status`, current period start and end dates, and the first invoice.

### Status on creation

| Status | When it occurs |
| --- | --- |
| `active` | Plan has no trial; first charge succeeded. |
| `trialing` | Plan has a `trialPeriodDays` configured. |
| `past_due` | Initial CIT failed. Rare — normally a `402` is returned on decline instead. |

## Errors

| Code | Meaning |
| --- | --- |
| `400` | Plan not found or inactive; or (record mode) the token carries no CIT mandate, or `firstPaymentId` doesn't resolve to a settled payment that charged this token. |
| `402` | Initial CIT charge declined (CIT mode), or the first-cycle MIT declined (record mode — the subscription is rolled back). |
| `409` | Duplicate `Idempotency-Key` with a conflicting request body. |
| `422` | Validation error — e.g. no card instrument provided, an expired/used nonce, or an invalid plan. |

```bash cURL
  -H "Content-Type: application/json" \

    "planId": 42,
    "customerEmail": "ada@example.com",
    "customerName": "Ada Lovelace",
    "card": { "nonceData": { "nonce": "<fresh nonce from JS SDK>" } }
  }'
```
