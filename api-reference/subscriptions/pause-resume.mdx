Pausing a subscription stops all renewal attempts without cancelling it, preserving the subscription record and all its history. Resuming restores billing and recalculates the next billing date forward from the current date — the customer is not charged for time elapsed while paused.

## Pause a Subscription

`POST /subscription/{id}/pause` suspends billing on an active subscription. It fires the `subscription.paused` webhook event and moves the subscription to `paused` status.

<Note>
  Only subscriptions in `active`, `trialing`, or `past_due` status can be paused. Attempting to pause a `cancelled`, `completed`, or already `paused` subscription returns a `400` error.
</Note>

### Request

**Endpoint:** `POST /subscription/{id}/pause`

### Headers

<ParamField header="Authorization" type="string" required>
  `Bearer prv_production_xxx` (production) or `Bearer prv_sandbox_xxx` (sandbox) — your merchant private API key.
</ParamField>

<ParamField header="Content-Type" type="string" required>
  `application/json`
</ParamField>

<ParamField header="Idempotency-Key" type="string">
  A UUID you generate per operation. Retrying with the same key returns the original response instead of repeating the operation. Recommended in production.
</ParamField>

### Path Parameters

<ParamField path="id" type="string" required>
  The UUID of the subscription to pause.
</ParamField>

### Request Body

<ParamField body="merchantCode" type="string" required>
  Your merchant account identifier.
</ParamField>

### Example

```bash
curl -X POST https://api.therius.io/v1/subscription/sub_abc123def456/pause \
  -H "Authorization: Bearer prv_production_your_key_here" \
  -H "Content-Type: application/json" \
  -d '{ "merchantCode": "MERCHANT_001" }'
```

## Resume a Subscription

`POST /subscription/{id}/resume` restores billing on a paused or suspended subscription, with slightly different behaviour depending on the current status.

| Current status | Behaviour on resume |
| --- | --- |
| `paused` | Billing restored. Next billing date = today \+ plan interval. |
| `suspended` | Therius attempts an immediate re-charge (MIT). Returns `402` if declined. |

<Warning>
  If resuming from `suspended` returns `402` (card declined), you must first update the payment method using `POST /subscription/{id}/payment-method` before retrying the resume.
</Warning>

On success, Therius fires `subscription.resumed`. If a `suspended` subscription is revived by a successful charge, it also fires `subscription.reactivated`.

### Request

**Endpoint:** `POST /subscription/{id}/resume`

### Headers

<ParamField header="Authorization" type="string" required>
  `Bearer prv_production_xxx` (production) or `Bearer prv_sandbox_xxx` (sandbox) — your merchant private API key.
</ParamField>

<ParamField header="Content-Type" type="string" required>
  `application/json`
</ParamField>

<ParamField header="Idempotency-Key" type="string">
  A UUID you generate per operation. Retrying with the same key returns the original response instead of repeating the operation. Recommended in production.
</ParamField>

### Path Parameters

<ParamField path="id" type="string" required>
  The UUID of the subscription to resume.
</ParamField>

### Request Body

<ParamField body="merchantCode" type="string" required>
  Your merchant account identifier.
</ParamField>

### Errors

| Code | Meaning |
| --- | --- |
| `400` | Subscription is not in a resumable state (e.g. already `active` or `cancelled`). |
| `402` | Resume from `suspended` failed — immediate re-charge was declined. |
| `404` | Subscription not found. |

### Example

```bash
curl -X POST https://api.therius.io/v1/subscription/sub_abc123def456/resume \
  -H "Authorization: Bearer prv_production_your_key_here" \
  -H "Content-Type: application/json" \
  -d '{ "merchantCode": "MERCHANT_001" }'
```
