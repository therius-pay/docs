`POST /payment/authorization` reserves funds on the cardholder's account without settling them. The authorization hold is typically valid for 7 days, though the exact window depends on the acquirer and card network. Call [Capture](/api-reference/capture) to settle the funds when you're ready to fulfill, or [Cancel](/api-reference/cancel) to release the hold if you can't fulfill the order.

## Request

**Endpoint:** `POST https://api.therius.io/v1/payment/authorization`

<ParamField header="Authorization" type="string">
  Your secret API key as a Bearer token: `Bearer sk_live_xxx` (production) or `Bearer sk_sandbox_xxx` (sandbox). Required unless you pass `key` in the request body.
</ParamField>

<ParamField header="Idempotency-Key" type="string">
  A UUID you generate per operation. Required in production. Retrying with the same key returns the original response without creating a duplicate hold.
</ParamField>

<ParamField header="Content-Type" type="string" required>
  Must be `application/json`.
</ParamField>

<ParamField body="key" type="string">
  Your merchant private API key. You can pass this in the body instead of the `Authorization` header, but the header is preferred.
</ParamField>

<ParamField body="merchantCode" type="string" required>
  Your merchant identifier, issued when your account is created.
</ParamField>

<ParamField body="orderCode" type="string" required>
  Your internal order reference. Must be unique per merchant.
</ParamField>

<ParamField body="amount" type="object" required>
  The amount to reserve.

      ISO 4217 currency code, e.g. `"USD"`, `"EUR"`, `"JPY"`.
    </ParamField>

    <ParamField body="value" type="integer" required>
      Amount in minor units. For USD, `4999` = \$49.99. For JPY, `5000` = Â¥5000.

    </ParamField>
  </Expandable>
</ParamField>

<ParamField body="shopper" type="object">

<ParamField body="webhookUrl" type="string">

<ParamField body="connectionCode" type="string">

## Response

<ResponseField name="status" type="string">
  Authorization outcome. One of:

  - `"authorized"` â€” funds are reserved successfully. Call [Capture](/api-reference/capture) to settle.
  - `"declined"` â€” issuer declined. Check `refusalCode`.
  - `"pending_3ds"` â€” cardholder must complete a 3DS challenge. Check `actionRequired`.
  - `"pending_action"` â€” payment requires an external action. Check `actionRequired`.
  - `"failed"` â€” processing error.
</ResponseField>

<ResponseField name="paymentCode" type="string">
  Therius's unique receipt ID (e.g. `"PC-1234567890"`). Store this â€” you'll reference it in your subsequent [Capture](/api-reference/capture) or [Cancel](/api-reference/cancel) call.
</ResponseField>

<ResponseField name="orderCode" type="string">
  Your `orderCode`, echoed back.
</ResponseField>

<ResponseField name="merchantCode" type="string">
  Your `merchantCode`, echoed back.
</ResponseField>

<ResponseField name="amount" type="object">
  The reserved amount in `{ currency, value, exponent }` format.
</ResponseField>

<ResponseField name="card" type="object">
  Card response including masked PAN, brand, type, and network transaction IDs.
</ResponseField>

<ResponseField name="token" type="object">
  Present if `tokenize: true` was requested. Contains `id` and `expirationDate`.
</ResponseField>

<ResponseField name="actionRequired" type="object">
  Present when `status` is `"pending_3ds"` or `"pending_action"`. Contains `type`, `url`, `paymentCode`, `barcode`, and `params`.
</ResponseField>

<ResponseField name="refusalCode" type="object">
  Present on decline. Contains `reason`, `reasonCode`, `originalReason`, `originalReasonCode`, and `recoveryAction` (`"retry"`, `"switch_method"`, or `"terminal"`).
</ResponseField>

<Note>
  Partial capture is supported. When you call [Capture](/api-reference/capture), you can pass an `amount` less than or equal to the authorized amount. For example, if you authorized $$99.00 but only shipped $$75.00 worth of goods, capture \$75.00 and the remaining hold is released automatically.
</Note>

<Warning>
  Authorization holds expire â€” typically after 7 days, but this varies by acquirer and card network. If you don't call [Capture](/api-reference/capture) before expiry, the hold is released and you'll need to re-authorize. Monitor hold age in your order management system.
</Warning>
